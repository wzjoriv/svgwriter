Export and import¶

Formats are found by name or file extension, so save and open usually need nothing else:

import svgwriter as svg

doc = svg.Document(120, 80)
doc.rect(10, 10, 100, 60, rx=8, fill="gold", stroke="black")
doc.text("svgwriter", x=60, y=48, font_size=16, text_anchor="middle")

doc.save("figure.svg")
doc.save("figure.png", scale=2)
doc.save("figure.pdf")
doc.save("figure.tex", standalone=True)
data = doc.export("eps")                      # bytes or str, without a file
again = svg.Document.open("figure.svg")
print(svg.formats.writers(), svg.formats.readers())

TikZ, EPS, PowerPoint, Word, Excalidraw and the polyline formats work from a flattened copy of the drawing: transforms, clipping, patterns and markers are worked into the shapes themselves. Masks and filters cannot be. PowerPoint and Word draw an element with a filter or mask as a picture of how it looks (one warning lists how many); everything else stays editable. save(..., fallback="drop") keeps those elements as shapes without the effect instead, and dpi= sets the pictures’ resolution (192 by default). The other flattened formats skip masks and filters with a warning; el.to_image(scale=...) turns any element into a picture by hand.

card = svg.Document(width=200, height=100)
card.rect(10, 10, 80, 50, rx=8, fill="teal", filter=svg.filters.drop_shadow())
# card.save("card.pptx")                   # the shadowed card becomes a picture
# card.save("card.pptx", fallback="drop")  # an editable card without its shadow

PowerPoint keeps SMIL as slide effects that start with the slide, each at its own begin (no clicks needed), and reading a deck turns them back into element.animate presets:

begin, dur, repeat, freeze and there-and-back values (pulse, color_cycle) carry over; an ease becomes PowerPoint’s accelerate and decelerate fractions, so curves are approximated. Shapes with an entrance effect are drawn in their visible state, since PowerPoint hides them until the effect. PowerPoint spins and scales about the shape’s centre, so a named or custom pivot (about=, anchor) other than the centre is not kept, and motion paths are followed without turning. Anything else (morph, draw, create, write, wipe, typewriter, skew, blink, sync-based begin) is dropped with one warning that lists it. PowerPoint and Word place pictures by their bounding box, so a rotated or skewed image comes out upright, and group opacity is multiplied into each shape’s own transparency. A radial gradient becomes a PowerPoint path gradient centred on the gradient’s centre, which matches circles and differs on ellipses. Excalidraw writes every outline as a line element, with Excalidraw’s own dash pattern; its elements have no holes, so the inside of a ring or of a letter such as “o” comes out filled.

Text stays text¶

Every format that can hold text keeps it as text, so it can be selected, searched and edited. Where a format cannot hold some text exactly, that text is drawn as its glyph outlines, which look the same but are shapes. Only raster formats turn text into pixels.

Pass text=False to pdf, tikz or eps to get exact outlines everywhere, for example when the reader of the file may lack the fonts:

doc.save("figure.pdf")                 # selectable text
doc.save("figure.pdf", text=False)     # glyph outlines only

PDF, EPS and TikZ read back as filled and stroked <path> elements with solid colours or gradients, stroke width, dashes, caps, joins and opacity, in user units with y pointing down (see Physical size). The PDF reader scans for objects (a broken xref table does not matter), inflates /FlateDecode streams, follows Form XObjects and gs alpha, and reads page 1 unless you pass page=. Images, clipping paths and text come in as <image>, clip-path and <text>. Text is decoded through the font’s /ToUnicode map, which most PDF writers embed. Glyphs placed one at a time are joined back into words, and the font family comes from the font’s name. Axial and radial shadings become gradients and tiling patterns become <pattern>. The EPS reader is a small PostScript interpreter. It handles paths, arc, painting, colours, line styles, gsave/grestore, transforms, image/colorimage, clip, shfill, show with findfont, and procedures and dictionaries with def. It honours %%BoundingBox and ignores operators it does not know. The TikZ reader takes \draw, \fill, \filldraw and \path with --, .. controls .., cycle, rectangle, circle and grid. It also reads colours from \definecolor and xcolor mixes, the common line options, shadings (top color, inner color and the like), nodes (with shapes and names), \tikzset styles, scope and \foreach. Other macros are not expanded.

page = svg.export.load("figure.pdf", page=0)
picture = svg.Document.open("figure.tex")

Page sizes¶

size= names a canvas instead of a width and height. Paper and card sizes keep their real units, so the viewBox counts in millimetres or inches and plain numbers inside are millimetres or inches; screen sizes are pixels. dpi= on raster exports then gives the real size in pixels:

poster = svg.Document(size="a4")                     # 210 x 297 mm; coordinates are millimetres
poster.rect(10, 10, 190, 277, fill="none", stroke="black", stroke_width=0.5)
poster.save("poster.png", dpi=150)                   # 1241 x 1755 pixels
wide = svg.Document(size="a4-landscape")             # any name turns with -landscape or -portrait
slide = svg.Document(size="slide-16:9")              # 1280 x 720, PowerPoint's default slide size
typed = svg.Document(size=svg.size.letter.landscape)  # svg.size.<name> is a PageSize (width, height, units)
svg.preset.size("poster-50x70", "50cm", "70cm")         # your own, also svg.size.poster_50x70
print(svg.preset.size.list()[:6], svg.size.poster_50x70.landscape)
svg.preset.size.unregister("poster-50x70")

svg.size.<name> gives a PageSize for every registered size with the name turned into an identifier (svg.size.slide_16_9, svg.size.instagram_story), so an editor completes it; .landscape and .portrait turn it. Document(size=...), Scene.size and a project’s size take a name or a PageSize.

Pages and slides¶

PDF and PowerPoint hold several drawings. Pass a list to export or save to write one page or slide per document, and use Document.open_all to read them all back as a list:

cover = svg.Document(160, 90)
cover.text("Results", x=80, y=50, font_size=20, text_anchor="middle")
svg.export.save([cover, doc], "report.pdf")             # two pages, each its own size
svg.export.save([cover, doc], "deck.pptx")              # two slides
pages = svg.Document.open_all("report.pdf")             # [Document, Document]
second = svg.Document.open("deck.pptx", slide=1)        # one slide, as before

A PDF page takes the size of its document. A PowerPoint deck has one slide size, so it fits the widest and the tallest drawing, and smaller drawings are centred on their slides. Other formats hold one drawing and raise ValueError for a list. The low-level load returns the list too when the page option is None (page=None for PDF, slide=None for PowerPoint); Document.open reads one page and Document.open_all reads every page, or wraps a single-page file in a list of one.

Physical size¶

A user unit is a CSS pixel, 96 to the inch, so a point is 4/3 of a unit and a millimetre is 96/25.4. Formats with a physical page keep the document’s true size: a svg.Document(210 * svg.mm, 297 * svg.mm) exports as a 595.28 × 841.89 pt A4 PDF page and EPS bounding box, and as a 7560000 × 10692000 EMU PowerPoint slide, and an 8.5 × 11 inch document as a 612 × 792 pt Letter page. TikZ pictures are drawn at 0.75 bp per unit, Word drawings at 9525 EMU per unit, and DXF, HPGL and G-code at 25.4/96 mm per unit. A raster has no physical size: dpi= sets how many pixels an inch of the document becomes (96 is scale=1), and pixels= asks for an exact pixel size instead.

a4 = svg.Document(210 * svg.mm, 297 * svg.mm)   # user units are millimetres through the viewBox
a4.rect(20, 30, 50, 10, fill="red")
a4.save("a4.pdf")                               # prints at 100% on A4

Readers work the other way: a PDF or EPS point reads as 4/3 of a unit and a TikZ 1cm as 96/2.54, so a file made elsewhere opens at its real size and an exported file reads back at the same size with every shape in the same place, measured in user units (a millimetre document comes back as 793.7 × 1122.5 units with no viewBox scaling).

A drawing made in plain numbers is in CSS pixels, so a 144-unit-wide figure prints 1.5 inches wide. When the numbers are meant as points (one unit, one point, as in many plotting tools), pass units_per_inch=72 to pdf, eps, tikz or, together with dpi=, to a raster format; sizes in mm, cm, in, pt or pc stay as they are:

chart = svg.Document(144, 72)                     # meant as 2 x 1 inches
chart.rect(0, 0, 144, 72, fill="none", stroke="black")
chart.save("chart.pdf", units_per_inch=72)          # 144 x 72 pt
chart.save("chart.pdf")                          # 108 x 54 pt: CSS pixels

Colour profiles¶

Every export draws in sRGB. icc= attaches an ICC profile, converting the pixels when it is not sRGB (LittleCMS does it in one pass and profiles are parsed once):

doc.save("figure.png", icc="srgb")               # tagged sRGB, pixels unchanged
doc.save("figure.png", icc="display-p3")         # pixels converted to Display P3, profile in iCCP
doc.save("figure.jpg", icc="display-p3")         # profile in APP2 segments
# doc.save("press.tif", icc=open("press.icc", "rb").read(), dpi=300)   # CMYK ink for a CMYK profile
# doc.save("print.pdf", icc=open("press.icc", "rb").read())            # PDF/X-style output intent

Wide-gamut colours (oklch(...), color(display-p3 ...)) keep their own space through theme palettes, theme expressions, mixing and gradient stops, so they are never clipped before they are combined. The pixels, though, are drawn by skia’s SVG renderer, which paints in sRGB: a colour outside sRGB is clipped to it when drawn, and icc="display-p3" then converts those sRGB pixels. The PNG is a correctly tagged Display P3 image of the sRGB rendering, not one that reaches the extra P3 gamut.

Format

icc=

PNG, APNG, JPEG

"srgb", "display-p3" or RGB profile bytes; the pixels are converted and the profile embedded

TIFF

the same, or CMYK profile bytes: the file is CMYK, flattened on white since ink has no alpha

PDF

"srgb" adds an sRGB output intent (as PDF/A expects); CMYK profile bytes add a PDF/X-style intent naming the press condition

A PDF keeps its colours as sRGB DeviceRGB: skia’s PDF backend writes no other colour space and no CMYK, so the intent is appended as an incremental update and a non-sRGB RGB profile is refused rather than silently reinterpreting the colours; a RIP converts the RGB to the press condition named by a CMYK intent. Without the extra, icc= raises an ImportError naming it.

Your own formats¶

A format is a class: the class line declares its name and extensions, and write, read or both say what it does. Creating the class registers it, so doc.save, doc.export, svg.Document.open and svg.Document.from_string use it at once.

class Lines(svg.Format, name="lines", extensions=(".lines",), binary=False):
    """One polyline per text line of x,y pairs."""

    def write(self, document, **options):
        lines = [" ".join(f"{x:g},{y:g}" for x, y in shape.to_path().nodes) for shape in document]
        return "\n".join(lines)

    def read(self, data, **options):
        out = svg.Document()
        for line in data.decode().splitlines():
            out.add(svg.polyline([tuple(map(float, p.split(","))) for p in line.split()],
                                 fill="none", stroke="black"))
        return out

doc.save("figure.lines")
again = svg.Document.open("figure.lines")
svg.formats.unregister("lines")                      # plugins and tests can clean up

binary=True (the default) means write returns bytes; multipage=True means write also takes a list of documents and read returns a list when its page option (page_option=, "page" by default) is None. svg.formats.writer(path) and svg.formats.reader(path) find a format by name, extension or file path. read_extensions= adds extensions the format only reads: the svg format also reads .svgz while .svgz writes through the svgz format, and Excalidraw also reads .json. A package can ship formats through the svgwriter.format entry-point group (see Extending svgwriter).

Diagrams¶

Graphviz (.dot, .gv) and Mermaid (.mmd, .mermaid) files load through their own command-line tools, so layouts match what those tools draw: svg.Document.open("graph.dot") runs dot -Tsvg, and svg.Document.open("flow.mmd") runs mmdc with SVG (not HTML) labels. The result is an ordinary document to edit, combine or export to any format. Install Graphviz or @mermaid-js/mermaid-cli, or point SVGWRITER_DOT / SVGWRITER_MMDC at the executables; a missing tool raises DiagramToolError with the install hint. Without mmdc, Mermaid flowcharts (graph / flowchart: node shapes, edge styles and labels, chains, & groups, subgraphs) are parsed and laid out by svgwriter itself, so they need no tool at all.

PlantUML (.puml) and D2 (.d2) load the same way through plantuml and d2. Math comes from LaTeX itself: svg.latex(r"\int_0^1 x^2\,dx = \frac{1}{3}", display=True) returns the typeset formula as outlines. Without TeX it falls back to Ziamath (pure Python, pysvgwriter[math]) and then to matplotlib’s mathtext; engine="tex", "ziamath" or "mathtext" picks one.

Office files¶

pip install "pysvgwriter[office]" adds PowerPoint, Word and Excel:

  • .pptx out: one slide per drawing (a list gives a deck), each outline an editable PowerPoint shape (curves, solid or gradient fill, outline with dashes, caps and joins, transparency, hyperlink), text as editable text boxes, images as pictures and SMIL as slide effects. In: shapes, pictures, text boxes and effects of a slide (svg.Document.open("deck.pptx", slide=2)) as native SVG elements and presets, with the same paints and links.

  • .docx out: the drawing as native Word shapes floating in one paragraph as tall as the drawing, with the same outlines, paints, text boxes and pictures as the PowerPoint export. In: paragraphs, headings (Title, Heading 1-6), bulleted and numbered lists and line breaks laid out top to bottom like Markdown, with each run’s bold, italics, underline, strike-through, size, colour and font as a styled <tspan>. Inline pictures and shapes take their place in the flow; floating ones keep their position, and their text boxes come back as text. Table cells are read as paragraphs.

  • .xlsx out: the drawing as a picture at its natural size.

Formulas made with svg.latex remember their source (the group’s data-latex attribute), so the PowerPoint and Word exports write them as native, editable Office equations instead of outlines. The LaTeX goes through MathML (latex2mathml) to Office Math: fractions, scripts, roots, sums and integrals, accents, bars, limits, \left/\right delimiters, matrices, text and Greek letters. Each equation is centred on the box the formula occupied, in Cambria Math at the drawn size; in Word it floats over the shapes, or becomes an equation paragraph when the drawing holds nothing else. LaTeX with no Office equivalent stays as outlines. Reading a deck back gives an equation’s characters as plain text, without its layout.

slide = svg.Document(320, 120)
slide.add(svg.latex(r"\int_0^1 x^2\,dx = \frac{1}{3}", display=True)).scale(2).place(160, 60)
slide.save("formula.pptx")      # an editable equation, not shapes

Without the extra these formats raise an ImportError that names the install command.

HTML pages¶

doc.save("page.html") writes a standalone page with the drawing inline. The SVG stays static; interaction is attached by the page, by element id:

# doc.save("page.html", title="Demo", css="#logo:hover { opacity: 0.7 }",
#          handlers={"logo": {"click": "this.style.fill = 'red'"}})

Opening an HTML file reads its first inline <svg>.
